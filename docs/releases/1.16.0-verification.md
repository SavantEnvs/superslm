# SuperSLM 1.16.0: test results

This page summarizes the testing behind 1.16.0's GPU frozen-prefix save and restore (`sslm_gpu_prefix_save`,
`sslm_gpu_prefix_restore`, the `SPX1` blob with backend 1). It is written for developers deciding whether to use the
feature. The release note, [`1.16.0.md`](1.16.0.md), describes the API. The raw logs and per-run records are kept on
the development branch, not here.

Test cells are named the way the test sources name them. Each source file lists its cells in its header.

## In short

- On the two GPUs tested, the NVIDIA GeForce RTX 2080 SUPER and the AMD Radeon RX 7900 XTX, every GPU save and
  restore cell is green with the D3D12 debug layer and GPU-based validation on, and so are the paged-KV GPU cells of
  steps G4 and G5 that the twins build on. The two cards gave the same check counts, all with 0 failures.
- A blob saved on one of the two cards is refused on the other with `SSLM_RESTORE_PRODUCER_MISMATCH`, in both
  directions, and a blob restores on the card that wrote it.
- The engine source of 1.16.0 equals 1.15.0's apart from the version number and the lifted labels, so these GPU
  runs, taken on the 1.15.0 tree, test the code that ships.

## The GPU save and restore cells

Both GPUs ran the same executables, built with MSVC 14.34 and Windows SDK 10.0.22621.0 from the `main` tree after
1.15.0 (engine version 1.15.0), on two Windows machines. Each piece ran alone, with no other GPU work on the machine.

| Piece | What it covers | RTX 2080 SUPER | RX 7900 XTX |
|---|---|---|---|
| GPU save/restore cells, debug layer on | the blob format, the pool and nested sharing, Busy, injected faults, the budget-stop snapshot, the derived ready and bind state (six cells) | 810 checks, 0 failures | 810 checks, 0 failures |
| Schema name hashes at GPU model map, debug layer on | the GPU map refuses a model with two colliding schema name hashes or a zero hash, and maps the renamed pair | 8 / 0 | 8 / 0 |
| Paged-KV GPU cells, step G5, debug layer on | 24 cells | 1,074 / 0, 0 skipped | 1,074 / 0, 0 skipped |
| Paged-KV GPU cells, step G4 except 1.9, debug layer on | 17 cells | 1,418 / 0, 0 skipped | 1,418 / 0, 0 skipped |
| Paged-KV GPU cell 1.9, debug layer off | the long randomized pool cell (135 creates, 279 adopts, 47 prefills, 118 resets, 125 releases, 118 prefix rebuilds) | 4,125 / 0 | 4,125 / 0 |

- The six save/restore cells are 258, 266, 23, 135, 75 and 53 checks on each card.
- In the paged-KV cells that count them, the debug layer reported no message at WARNING or above, on either card. The allocation failures the
  fault cell injects are expected, and the cell checks each one's refusal.
- Cell 1.9 runs with the debug layer off. Under GPU-based validation it takes about 90 minutes on the RTX 2080
  SUPER, and it ran alone so as to stay in bounded time.

## Different card, refused

- The RTX 2080 SUPER saved a 15,736-byte blob (producer vendor `10de`, device `1e81`) and restored it on itself: 14
  checks, 0 failures.
- The RX 7900 XTX refused that blob as another card's, with a null out-handle, then saved its own (vendor `1002`,
  device `744c`, 15,736 bytes) and restored it on itself: 14 checks, 0 failures.
- The RTX 2080 SUPER refused the RX 7900 XTX's blob with `SSLM_RESTORE_PRODUCER_MISMATCH` and a null out-handle: 8
  checks, 0 failures.

## The test catches a broken build

The Busy cell was rebuilt against a deliberately broken library, with the submission guard removed from the GPU
restore. On the RTX 2080 SUPER it went red (21 checks, 3 failures), naming the Busy rule, so the cell can tell a
restore that ignores in-flight work from a correct one.

## Known issue

- RTX 50-series (Blackwell) GPUs fail parts of the GPU test suite; under investigation; use the CPU backend there. These results are from the two cards above
  only, and claim nothing for any other GPU.

## Not covered by this page

These are not part of the results above:

- **Byte identity across backends and cards (cell 4.6).** Whether the same prefix built by prefill on the CPU and on
  each GPU gives byte-equal `SPX1` rows, and whether the two GPUs agree with each other, was not measured. Until it is,
  a GPU blob restores only on the card that wrote it, as above.
- **GPU speed (cell 10.4).** No GPU restore-against-prefill timing is published for 1.16.0.
- **Real-model GPU runs (cells 4.4 and 6.5).** The GPU cells above use the synthetic test models, not the real 0.5B
  and 1.5B artifacts.
- **Across releases on the GPU and on Windows.** 1.13.1's GPU sequence saves read by this release's GPU build
  (cell 9.10 on 1.16.0), and the 1.14.0 blob refusal on the MSVC build (cell 9.5's Windows half).
